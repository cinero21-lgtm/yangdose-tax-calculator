# 통화녹취 + 전사 파일

사진과 **정책이 다르다.** 사진은 올린 뒤 폰에서 치우지만, 통화녹취는 올린 뒤
**폰에 그대로 둔다(복사).** 녹취는 10분 통화가 1MB 정도로 작고, 사용자가 폰에서도
바로 듣기를 원하기 때문이다.

| | 업로드 후 폰의 원본 |
|---|---|
| 사진·동영상 | 휴지통으로 이동 (30일 뒤 삭제) |
| 통화녹취·전사 | **그대로 둔다** |

통화 녹음 폴더는 **사진·동영상 훑기에서 아예 제외된다.** 확장자만 맞춰서는 부족하다 —
`.3gp` 녹음이 동영상으로 분류돼 `migrate` 에 휩쓸리면 "폰에 남긴다"는 정책이 정면으로
뒤집힌다. 폴더 단위로 뺀다.

같은 이유로 자동 탐색은 겹칠 때 **더 구체적인 쪽**을 고른다. `Recordings` 를 통째로
훑으면 `Recordings/Voice` 의 음성메모까지 통화녹취로 올라간다.

## 먼저 probe 로 실물을 본다

녹음 폴더 경로도, 파일명 형식도, 전사가 파일로 저장되는지도 기종·앱마다 다르다.
추측으로 설정하면 엉뚱한 곳을 뒤지거나 잘못 분류한다.

```sh
photo-autobackup.sh probe
```

읽기 전용이다. 아무것도 올리거나 지우지 않는다. 여섯 가지를 보고한다:

1. 녹음 폴더 후보별 존재 여부와 파일 수
2. 확장자별 분포
3. 파일 이름 샘플과 **각각에 대한 수신/발신 판정 결과**
4. 전사 파일 검출 여부
5. `termux-call-log` 가용 여부
6. 현재 설정

## 수신/발신 판정 — 추측하지 않는다

3단계로 시도하고, 안 되면 미분류로 보낸다.

| 순서 | 방법 | 실패하면 |
|---|---|---|
| 1 | 파일명이 `CALL_IN_PATTERN` / `CALL_OUT_PATTERN` 에 걸리는가 | 2로 |
| 2 | `termux-call-log` 항목 시각이 파일 mtime 과 `CALL_LOG_WINDOW`초 이내인가 | 3으로 |
| 3 | **`통화녹취_미분류` 폴더로** | — |

3번이 이 설계의 핵심이다. 반쯤 맞는 분류는 분류가 아니다. 한 건이라도 잘못 들어가면
"수신녹취 폴더에 있으니 수신"이라는 전제가 무너지고, 전체를 다시 확인해야 한다.

`probe` 의 3번 항목이 각 파일에 대해 어떤 판정이 나오는지 미리 보여주므로, 미분류가
많으면 `CALL_IN_PATTERN` 을 실제 파일명에 맞게 고치면 된다.

### 통화기록 권한

`termux-call-log` 는 Termux:API 앱과 통화기록 권한이 있어야 동작한다.

> 설정 > 애플리케이션 > Termux:API > 권한 > 통화기록 허용

없어도 파일명 판정은 그대로 되고, 못 가린 것만 미분류로 간다.

## 전사 파일

녹음과 **같은 이름**의 텍스트 파일을 찾아 **녹음과 같은 폴더**로 함께 올린다.

```
수신녹취/2026/2026-08/통화녹음 홍길동 260819_143200.m4a
수신녹취/2026/2026-08/통화녹음 홍길동 260819_143200.txt
```

짝을 붙여 두는 이유: 나중에 "이 통화가 무슨 내용이었나"를 찾을 때 음성과 텍스트가
떨어져 있으면 둘을 다시 잇는 일이 생긴다. 이름이 같고 폴더가 같으면 그럴 일이 없다.

짝이 없는 전사 파일은 버리지 않고 미분류로 올린다.

### 전사가 파일로 저장되지 않는 경우

삼성 「텍스트 변환 어시스트」를 비롯한 상당수 기능은 텍스트를 **앱 내부에만** 두고
파일로 내보내지 않는다. 그러면 rclone 이 볼 수 없다. `probe` 의 4번 항목이 이걸
알려준다. 4번은 두 단계로 본다 — 녹음 폴더 옆을 먼저 보고, 없으면 폰 전체를 한 번
더 훑는다. 둘 다 0 이어야 "어디에도 없다"고 단정한다.

#### 실기기 확인 — Galaxy Z Fold 8 / One UI

`probe --deep` 으로 세 경로를 끝까지 훑은 **최종 결론**이다. 같은 질문이 다시
나오면 여기서부터 시작해라 — 처음부터 되풀이할 필요가 없다.

| 경로 | 결과 |
|---|---|
| 일반 폴더의 전사 파일 | 없음 (확장자 무관 전수 조사) |
| `Android/data` | 안드로이드가 목록을 차단 |
| ContentProvider | **존재하지만 전부 권한 거부** |

APK 매니페스트에서 실제 provider 이름까지 뽑아냈다.

```
com.sec.android.app.voicenote.data.VNAIProvider        ← 전사·AI 담당으로 보인다
com.sec.android.app.voicenote.data.VNProvider
com.sec.android.app.voicenote.data.CategoryDBProvider
com.sec.android.app.voicenote.data.FinderProvider
com.sec.android.app.voicenote.data.ManageTrashProvider
com.sec.android.app.voicenote.CapsuleProvider
```

전부 `Error while accessing provider` 로 거부된다. 읽으려면
`...VNAIProvider.READ_PERMISSION` 이 필요하고 그 권한은 **시스템 서명 앱에만**
나간다. **루팅 없이는 여기까지가 끝이다.** 더 팔 기계 경로는 없다.

이건 "확인 못 했다"가 아니라 **"확인했고 거부당했다"** 이다. 다시 조사하지 마라.

남은 비루팅 경로는 앱 UI 뿐이다 — `⋮` 의 '텍스트 내보내기'로 사람이 저장하거나,
접근성 자동화(Tasker+AutoInput)로 그 메뉴를 대신 누르는 것.

#### 그 밖에 이 기종에서 확정된 것

- 통화 녹음 앱은 전사·요약을 **한다.** 앱 화면에 통화마다 요약 한 줄이 붙는다
- 그러나 그 결과를 공유 저장소에 **파일로 내보내지 않는다.** 폰 전체를 훑어도
  `txt/md/json/srt/vtt` 가 한 건도 없다
- 녹음 파일명은 `통화 <상대 번호 또는 이름>_<YYMMDD>_<HHMMSS>.m4a` 이고,
  **수신/발신 표시가 없다** → 방향 판정은 통화기록 권한에 전적으로 의존한다

#### 정해진 방침 — 전사는 Gemini 가 한다

사용자가 정했다: **녹취(음성)만 드라이브에 올리고, 전사는 드라이브에 연동된
Gemini 에게 맡긴다.** 폰에서 텍스트를 뽑아내려 애쓰지 않는다.

이 방침에서 스킬이 할 일은 **음성을 제때 정확한 폴더에 올려 두는 것 하나**다.
그것은 이미 `calls`/`watch` 가 하는 일이며, 전사 짝 업로드 기능은 그대로 두되
(다른 기종에서는 파일이 나온다) 이 기기에서는 0건인 게 정상이다.

`probe` 4번이 0건이라고 해서 통화녹취 백업이 실패한 것이 아니다. **전사가 없어도
녹취 업로드는 독립적으로 동작한다.**

텍스트 파일이 꼭 필요한 개별 통화는 앱의 **공유/내보내기**로 저장한 뒤 녹음과 같은
이름으로 맞춰 두면 짝 업로드에 그대로 실린다.

## 켜기

`probe` 결과가 납득되면 설정 파일에서 켠다.

```sh
# ~/.config/photo-autobackup/config.env
CALL_ENABLED=1
```

기본이 꺼짐인 이유는 통화 녹취에 **상대방 음성**이 담기기 때문이다. 사용자가
의식적으로 켜기 전에 클라우드로 올라가면 사고다.

```sh
photo-autobackup.sh calls      # 1회 스윕
photo-autobackup.sh watch      # 상시 — 통화가 끝나면 자동으로 올라간다
```

`watch` 는 `CALL_ENABLED=1` 일 때 사진 훑기와 함께 통화녹취도 매 주기에 훑는다.
inotify 가 있으면 파일이 생기는 즉시 반응한다.

## 두 번째 스윕부터는 빠르다

복사 정책은 파일이 폰에 계속 남는다. 장부(`~/.local/share/photo-autobackup/uploaded.tsv`)에
올린 파일의 **해시·크기·수정시각**을 적어 두고, 크기와 수정시각이 그대로면 해시조차
계산하지 않고 넘어간다.

해시까지 다시 계산하면 통신은 아껴도 CPU 는 못 아낀다. 녹취는 지우지 않으므로
보관함이 계속 커지는데, `watch` 가 주기(기본 60초)마다 보관함 전체를 다시 해싱하면
배터리를 태운다. 크기·수정시각 확인에서 끊어야 보관함이 커져도 주기 비용이 늘지 않는다.

파일 내용이 바뀌면(전사가 나중에 갱신되는 경우 등) 다시 올린다.

## 훑는 범위는 한 겹이다

녹음 폴더 바로 아래만 본다. `Recordings/Call` 이 없는 기기에서는 `Recordings` 를
쓰게 되는데, 재귀로 훑으면 `Recordings/Voice` 의 음성메모까지 통화녹취로 올라간다.
날짜별 하위 폴더에 녹음이 쌓이는 기기라면 `CALL_DIRS` 에 그 폴더를 직접 적어라.

## 통화녹취를 끄면 그 폴더는 사진 이관 대상이 된다

`CALL_ENABLED=0` 일 때는 통화 폴더를 사진·동영상 훑기에서 빼지 않는다. 빼면서
`calls` 도 안 돌면 그 안의 파일은 어느 쪽으로도 백업되지 않는데 `verify-empty` 는
"폰이 비었다"고 보고하게 된다. 켜지 않을 거라면 그 폴더의 미디어는 사진 정책
(올리고 폰에서 치움)을 따른다는 뜻이므로, 원치 않으면 통화녹취를 켜라.

## 드라이브에서 활용하기

전사가 텍스트 파일로 올라가면 구글드라이브가 **내용까지 전문 검색**한다. 연동된
Gemini 에게 "지난달 홍길동과 한 통화들 요약해줘" 같은 요청도 가능해진다.

폴더가 수신/발신으로 갈려 있으므로 "내가 건 전화만" 같은 범위 지정도 폴더로 된다.

## 문제 해결

| 증상 | 원인·대처 |
|---|---|
| `녹음 폴더를 찾지 못했다` | 통화 녹음 설정이 꺼져 있거나 경로가 다르다. `probe` 1번 확인 후 `CALL_DIRS` 직접 지정. 여러 경로는 **줄을 바꿔** 적는다 — 공백으로 나누면 공백이 든 경로가 깨진다 |
| 90초 넘는 통화가 미분류로 간다 | 오래된 버전이다. 녹음 파일 시각은 통화 *종료* 시각이라 통화 시간을 더해 대조해야 한다. `update` 로 갱신해라 |
| 전부 미분류로 간다 | 파일명에 단서가 없고 통화기록 권한도 없다. Termux:API 권한을 켜거나 `CALL_IN_PATTERN` 을 실제 파일명에 맞춘다 |
| 전사가 안 올라간다 | `probe` 4번이 0건이면 앱이 파일을 안 만드는 것이다. 이 기기(Z폴드 8)에서는 정상이며, 전사는 드라이브의 Gemini 가 맡는다 (위 참고) |
| 매 주기가 느리다 | 장부가 지워졌을 수 있다. 한 번 더 돌면 다시 쌓인다 |
| 폰 용량이 부담된다 | 이 스킬은 녹취를 지우지 않는다. 오래된 것은 직접 정리하거나 별도 정책을 논의해라 |

## .3gp 는 동영상 목록에서 뺐다

`.3gp` 는 통화 녹음에도, 오래된 휴대폰 영상에도 쓰인다. 동영상으로 취급하면
자동 탐색 밖의 폴더(예: 샤오미 `MIUI/sound_recorder/call_rec`)에 있는 통화 녹음이
`migrate` 에 휩쓸려 폰에서 사라진다. 폴더 기준 제외로는 못 막는다.

그래서 `VIDEO_EXTENSIONS` 에서 `.3gp` 를 뺐다. 녹음을 잃는 쪽이 오래된 `.3gp`
영상을 안 올리는 쪽보다 훨씬 나쁘기 때문이다. `.3gp` 영상을 꼭 올려야 한다면
설정에서 `VIDEO_EXTENSIONS` 에 다시 넣되, 통화 녹음이 그 확장자로 저장되지 않는지
`probe` 로 먼저 확인해라.

## 환경변수가 설정 파일을 이긴다

한 번만 다르게 돌려 보고 싶을 때 쓴다.

```sh
DRY_RUN=1 photo-autobackup.sh migrate      # 이번만 예행연습
CALL_ENABLED=1 photo-autobackup.sh calls   # 설정을 바꾸지 않고 한 번만
```

설정 파일이 환경변수를 이기면, 예행연습이 진짜 실행이 되어 사진이 지워진다.
