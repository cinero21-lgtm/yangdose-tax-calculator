# 사진 자동 백업 & 폰에서 비우기 (안드로이드)

촬영 → 구글드라이브 업로드 → **업로드 검증** → 폰에서 치우기. 이 세 단계를 폰 안에서
스스로 도는 데몬으로 만들어 준다. Claude가 사진 한 장씩 처리하는 게 아니라, 폰에
자동화를 **설치해 주는** 스킬이다.

## 두 가지 작업을 한다 — 어느 쪽인지 먼저 가려라

사용자가 원하는 게 둘 중 무엇인지에 따라 안내가 완전히 달라진다.

| | 언제 | 명령 |
|---|---|---|
| **전량 이관** (1회성) | "지금 폰에 있는 사진 전부 옮기고 폰 비워줘" | `migrate` |
| **상시 자동화** | "앞으로 찍는 사진은 알아서 올라가게" | `watch` |

보통은 **전량 이관을 먼저 하고, 그다음 상시 감시를 띄우는** 순서가 맞다. 전량 이관은
다루는 양이 크고 되돌리기 부담이 있으므로 `references/migration.md`의 런북을 그대로
따라가라 — 특히 예행연습(DRY_RUN) 단계를 건너뛰지 마라.

## 먼저 알아야 할 것

이 자동화는 폰 쪽에서 돌아야 하므로 안드로이드에서는 **Termux**가 필요하다. 구글 포토
'기기에서 삭제'와 다른 점은, 원본 화질 그대로 내 드라이브 폴더에 쌓이고, 언제 무엇이
지워졌는지 기록이 남고, 30일 안에는 되돌릴 수 있다는 것이다.

**아이폰이면**: iOS는 백그라운드 스크립트를 못 돌린다. 단축어(Shortcuts) 자동화로
비슷하게 만들 수 있지만 동작이 제한적이다 → `references/ios-note.md`를 읽고 안내해라.

## 안전 모델 — 여기가 이 스킬의 핵심

사진은 되돌릴 수 없는 자산이다. 그래서 삭제는 세 겹으로 막아 뒀고, 사용자에게도
이 점을 설명해 주는 게 좋다:

1. **검증 후에만 치운다.** 업로드가 끝나면 구글드라이브가 알려주는 MD5와 폰에 있는
   파일의 MD5를 맞춰 본다. 하나라도 어긋나거나 해시를 못 읽으면 원본을 건드리지 않는다.
2. **바로 지우지 않는다.** 검증을 통과한 파일은 완전 삭제가 아니라 Termux 안의
   휴지통으로 옮긴다. 갤러리에서는 사라지지만 파일은 기본 30일 남아 있고
   `restore` 한 방이면 원래 자리로 돌아온다.
3. **기록이 남는다.** 옮긴 파일마다 원래 경로·휴지통 경로·드라이브 경로·해시가
   `manifest.tsv`에 쌓인다.

처음 도입할 때는 `DRY_RUN=1`로 하루 돌려서 무엇이 대상인지 눈으로 확인시키는 게 좋다.
이걸 건너뛰면 사용자가 의도치 않은 폴더(스크린샷, 다운로드 이미지)까지 비워지는 걸
나중에 발견하게 된다.

## 설치 흐름

사용자에게 물어봐야 할 것부터 확인해라. 답이 없으면 괄호 안 기본값으로 간다.

- 어느 폴더를 비울까 (`DCIM/Camera`만) — 스크린샷까지 원하는지 꼭 확인해라
- 드라이브 어디에 쌓을까 (`PhoneCamera/연/연-월/`)
- 동영상도 올릴까 (아니오 — 데이터 요금이 커진다)
- 휴지통 보관 기간 (30일)

그다음 순서대로 진행한다:

1. **Termux 준비와 rclone 구글드라이브 연결** → `references/android-setup.md`를 읽고
   그대로 안내해라. 여기가 유일하게 사람 손이 꼭 필요한 구간이다(구글 계정 인증).
2. **설치**: `scripts/install.sh`를 폰의 Termux로 옮겨 실행한다. 패키지 설치,
   저장소 권한, 스크립트 배치, 설정 파일 생성, 부팅 자동 실행 등록까지 한 번에 한다.
3. **설정 조정**: `~/.config/photo-autobackup/config.env`를 위에서 물어본 답에 맞춘다.
   각 항목의 의미는 `scripts/config.example.env`에 주석으로 달려 있다.
4. **진단**: `photo-autobackup.sh doctor`. 통과 못 하는 항목이 있으면 그걸 먼저 해결해라.
   특히 감시 폴더 쓰기 권한이 없으면 업로드는 되는데 삭제만 조용히 실패한다.
5. **예행연습**: `DRY_RUN=1`로 `once` 한 번. 로그에 뜨는 대상 목록을 사용자와 같이 본다.
6. **가동**: `DRY_RUN=0`으로 되돌리고 `watch`. Termux:Boot 앱을 한 번 열어 두면
   재부팅 후에도 알아서 뜬다.

## 명령어

`~/bin/photo-autobackup.sh <명령>`

| 명령 | 하는 일 |
|---|---|
| `setup [폴더이름]` | 폰 상태를 읽어 설정을 자동으로 맞추고, 고칠 수 있는 건 고친다 |
| `migrate [--yes]` | 폰에 있는 사진을 **전부** 옮기고 폰을 비운다(1회성). 계획을 먼저 보여주고 `yes`를 받아야 진행 |
| `verify-empty` | 폰에 사진이 남았는지, 어디에 몇 건인지 확인 |
| `once` | 한 번 훑어서 업로드+검증+휴지통 이동. cron/Tasker에서 부르기 좋다 |
| `watch` | 계속 감시. inotify가 있으면 촬영 즉시, 없으면 60초 주기 |
| `doctor [--fix]` | 상태 점검. `--fix`면 패키지 설치·권한 화면 열기 등 자동 수리 |
| `status` | 대기 건수, 휴지통 용량, 누적 백업 수, 최근 로그 |
| `restore <패턴>` | 휴지통에서 원래 자리로 되돌린다. `all`이면 전부 |
| `purge` | 보관 기간 지난 것 완전 삭제 (`once`가 끝날 때도 자동 실행) |
| `reset-failures` | 실패 카운터 초기화. 원인을 고친 뒤에 쓴다 |

## 전량 이관에서 특히 주의할 것

- **전부 쓸어담지 않는다.** 앱 캐시(`Android/data`), 썸네일(`.thumbnails`), 숨김 파일은
  일부러 제외한다. 이걸 올리면 드라이브가 쓰레기로 차고, 지우면 앱이 깨진다.
  사용자가 "하나도 남기지 말라"고 해도 이 제외는 유지하고, 무엇을 제외했는지 알려 줘라.
- **용량을 먼저 맞춰 봐라.** 계획 출력에 총 용량과 드라이브 여유 공간이 같이 나온다.
  넘으면 중간에 실패가 쏟아지므로 시작 전에 정리하는 게 맞다.
- **이관 직후에는 폰 용량이 안 비어 보인다.** 원본이 30일 휴지통에 남아 있기 때문이다.
  확인이 끝난 뒤 `RETENTION_DAYS`를 줄이고 `purge`해야 실제로 공간이 생긴다.
  이 점을 미리 말해 주지 않으면 "안 지워졌다"는 오해가 생긴다.
- **몇 시간 걸린다.** 중간에 끊겨도 다시 실행하면 남은 것만 이어서 한다.
  Wi-Fi 전용(`REQUIRE_WIFI=1`)을 켜라고 권해라.

## "안 된다"고 할 때 — 추측하지 말고 이 순서로

사용자가 막연히 안 된다고 하면 원인을 상상하지 마라. 폰에서 스스로 진단하게 만들어 뒀다.

```sh
photo-autobackup.sh setup     # 폰 상태를 읽어 자동 교정. 여러 번 실행해도 안전
```

`setup`은 저장소 권한을 요청하고, **사진이 실제로 어디 있는지 폰에서 직접 찾아** 감시 폴더를
그 위치로 맞추고, 없는 패키지를 깔고, 권한 설정 화면을 띄운다. 그래도 남는 게 있으면
무엇이 문제인지 화면에 찍는다. 그 출력을 그대로 받아서 읽어라.

원인 중 압도적으로 흔한 두 가지:

1. **감시 폴더 경로가 틀렸다.** `DCIM/Camera`를 가정했는데 기기·앱마다 실제 위치가 다르다.
   `doctor`가 "감시 폴더에는 0건인데 폰에는 N건"으로 잡아내고, `setup`이 자동으로 고친다.
2. **안드로이드 11+ 저장소 권한이 없다.** 업로드는 되는데 삭제만 조용히 실패한다.
   `doctor --fix`가 해당 설정 화면을 폰에 띄워 주지만, 토글을 켜는 건 사람이 해야 한다.

Claude가 사용자 폰에 직접 접근할 수는 없다. 그러니 "제가 확인해 보겠습니다"라고 하지 말고,
위 명령을 실행해 출력을 달라고 해라 — 그게 유일하게 정확한 경로다.

## 문제가 생겼을 때

증상별 대처는 `references/troubleshooting.md`에 정리돼 있다. 가장 자주 나오는 세 가지만
미리 알아 두면 좋다:

- **업로드는 되는데 폰에서 안 지워진다** → 안드로이드 11+ 저장소 권한 문제다.
  Termux 앱 정보에서 '모든 파일 접근 허용'을 켜야 한다.
- **잠들면 멈춘다** → 배터리 최적화에서 Termux를 제외해야 한다.
- **`watch`가 부팅 후 안 뜬다** → Termux:Boot 앱을 설치하고 한 번 실행해야 등록된다.

로그는 `~/.local/share/photo-autobackup/autobackup.log`에 쌓인다. 사용자가 뭔가
이상하다고 하면 추측하지 말고 이 로그와 `doctor` 결과부터 받아라.

## 스크립트를 고칠 때

`tests/test_harness.sh`가 rclone과 폰 없이도 로직을 검증한다(가짜 rclone을 PATH에
끼워 넣고 임시 HOME에서 돈다). 정상 경로, 업로드 실패, 해시 불일치, 동명이인 파일,
DRY_RUN, 재검증, 복구, 실패 재시도 중단까지 17건을 확인한다. 스크립트를 수정했으면
`bash tests/test_harness.sh`를 돌려서 전부 PASS인지 보고 나서 폰에 올려라 —
사진을 지우는 코드라 회귀가 곧 데이터 손실이다.
